# art-canvas

общий холст для рисования. любой зашедший регистрируется и рисует на одном холсте
в реальном времени, а потом может посмотреть, кто что рисовал.

## что умеет

- **регистрация** по логину и паролю, сессия в httpOnly-cookie. пароли хранятся
  как pbkdf2-hmac-sha256 с солью, не в открытом виде
- **живой обмен штрихами** через websocket: рисуешь — остальные видят сразу,
  вместе с курсорами и именами участников
- **история «кто что рисовал»** — каждая операция хранится с автором, в админке
  видно ленту действий и можно убрать любую отдельную операцию
- **камера**: перенос холста (инструмент «перенос», пробел+тяга, средняя кнопка,
  колесо, два пальца на тачскрине), зум колесом с ctrl и кнопками, миникарта
  в углу с рамкой текущего обзора
- **ластик как кисть** — стирает по всей пройденной линии с толщиной кисти,
  а не по прямой от начала до конца

## как устроено

холст хранится не картинкой, а **списком операций**. каждая операция — это
`stroke`, `erase` или `text` с координатами в мировой системе, цветом и автором.
каждый клиент перерисовывает операции сам, поэтому рисунок одинаковый у всех и
можно посмотреть, кто какую операцию добавил.

это даёт историю по авторам бесплатно и не требует ни хранения картинок, ни
сервера с бинарным состоянием холста.

```
app.py              flask + flask-sock + sqlite, ~25 КБ
static/index.html   разметка
static/app.js       клиент: рисование, камера, websocket
static/style.css    тёмная тема, один акцент
```

## запуск

```bash
python3 -m venv venv
venv/bin/pip install flask flask-sock gunicorn

# админ задаётся через окружение, пароль в коде не хранится
export ART_ADMIN_LOGIN=admin
export ART_ADMIN_PASSWORD='сюда-пароль'

venv/bin/gunicorn -w 1 --threads 16 -t 0 --worker-class gthread \
    -b 127.0.0.1:8110 app:app
```

база создастся сама в `data/art.db` при первом запуске.

### за nginx

 websocket требует апгрейда соединения:

```nginx
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

location /ws {
    proxy_pass http://127.0.0.1:8110;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_read_timeout 3600s;   # соединение живёт пока открыт холст
}
```

## настройки

| переменная | что делает |
|---|---|
| `ART_ADMIN_LOGIN` | логин админа, которому доступна админка |
| `ART_ADMIN_PASSWORD` | его пароль, в коде не хранится |

## устройство данных

```
users     id, login, phash, salt, role, color, created_at
sessions  token, user_id, created_at
ops       id, user_id, op, payload, created_at
```

`payload` — json операции. `role=user` рисует и отменяет своё, `role=admin` ещё
может чистить холст и убирать чужие операции.

## что стоит учитывать

- каждая операция валидируется на сервере: неизвестный тип, мусорные координаты
  и битый цвет отбрасываются, точка в штрихе не может быть длиннее 4000
- список операций подрезается до 20000 последних, чтобы база не росла бесконечно
- пароли админа не хранятся в базе вовсе, они сверяются с переменной окружения
